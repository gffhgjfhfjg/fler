本模块采用典型的 Android 分层架构：
- 入口层：`FlerApplication` 通过 `@HiltAndroidApp` 启用 Hilt，并在 `onCreate` 中调用 `NativeLoader.load()` 加载 `fler_jni`；`MainActivity` 为唯一 Activity，使用 Compose `setContent` 挂载主题与根导航图 `AppNavGraph`。
- UI 层：按功能划分 `app/navigation`、`app/theme`、`features/*`（so_editor、project、settings、mcp、engine、onboarding 等），所有界面均为 Compose Screen + ViewModel 组合。
- 核心层 `core/`：`di/` 下通过 Hilt `@Module` + `@InstallIn(SingletonComponent::class)` 提供 OkHttpClient、数据库等单例；`jni/` 封装 JNI 绑定（CapstoneBindings、RizinBindings、ElfParserBindings、KeystoneBindings）及 `NativeLoader`；`analysis/` 定义 `BinaryAnalysisEngine` 抽象与 RizinEngine/SelfAnalysisEngine 实现；`service/` 包含引擎下载、APK 提取、备份等基础设施；`mcp/` 实现 MCP JSON-RPC HTTP 服务器。
- 数据层 `data/`：Room 实体（`entity/*`）、DAO（`dao/*`）与 `AppDatabase`。
- 原生层 `cpp/`：CMake 构建两个目标——`fler_native`（静态库，仅 elf_parser）和 `fler_jni`（共享库，JNI 桥接），静态链接 `libcapstone.a`、`libkeystone.a` 以及 `librz_*.a`（Rizin 子模块），头文件通过 `include/capstone`、`include/rizin`、`keystone_include` 暴露。
- 依赖方向：UI → core → data，JNI 桥接作为单向边界调用 C++ 静态库，不反向依赖上层。
